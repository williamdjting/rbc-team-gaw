Dataset and experiment setup

Training data Regional feature data from Experiment 02

All three model folders use the same B.C. region feature sets under the 02/regions/ pipeline. The feature parquet files are built per region and per year and then pooled across 2018–2021 for training.

Evaluation logic Train on 2018–2021, tune on 2022, evaluate on 2023

Thresholds were selected per Fire Centre and configuration using 2022 F1, then applied unchanged to 2023. This keeps the evaluation time-based and avoids leakage across years.

Target Recorded hotspot activity, not ignition certainty

The label is target_recorded_detection: whether FIRMS reported at least one hotspot in the cell on that day. That is a detection target, not a verified fire start or confirmed ignition event.

Modeling choices Cell-only and cell-plus-neighbours

Each experiment runs both feature sets, with the same core feature design used in the earlier learned baselines. The neighbor version intentionally adds local spatial context from nearby cells.

Prototype status

What the results suggest

  • CatBoost is a strong baseline. The undersampled CatBoost setup is competitive and interpretable, with mean F1 around 0.507.
  • TabPFN is promising but still early. The hybrid run reached a higher mean F1 (~0.526) and mean AP (~0.469), suggesting the active-row model may be useful, but the outcome should still be read as a prototype rather than a final production model.
  • Feature context matters. The cell_plus_neighbours feature set is consistently stronger than cell_only in the 05–07 runs, which supports the spatial signal hypothesis.
  • Quiet vs active separation matters. The hybrid design is deliberately structured to use the best of both worlds: TabPFN where the label is more informative and CatBoost where the majority of rows are quiet and need a stable baseline.

TabPFN research angle

Why it matters TabPFN is especially strong on small labelled tabular datasets

It is a pretrained transformer for tabular data, and a number of studies show strong performance when the dataset is modest and the task is structured tabular prediction. This makes it a plausible fit for rare-event hotspot detection where the positive class is small but the full data volume is large.

What the literature says Three wildfire studies use TabPFN, but none match our exact forecasting task

One study on Canadian wildfire propagation type, one on wildfire susceptibility mapping in Victoria, and one on post-wildfire debris-flow prediction all reported competitive performance. However, none of them focus on next-day hotspot detection or early wildfire detection in the same spatiotemporal framework as this project.

Main caveat Our use case is still an open gap

The review suggests there is no direct TabPFN benchmark for early detection or next-day ignition forecasting in BC. That is good for the research story: this project is exploring an under-studied setting, not simply reproducing an existing pipeline.

Practical caveats Context size and data leakage are crucial

TabPFN context is capped, and scoring many millions of rows is expensive. The review also stresses that random train/test splits can be too optimistic in wildfire work. For us, a time-based split (train on 2018–2021, evaluate on 2023) is the right design principle.

Technical notes: how the metrics and models work

Mean F1 F1 combines precision and recall into one score

For rare-event wildfire detection, precision tells us how many predicted hotspots were real, and recall tells us how many true hotspots we caught. F1 is the harmonic mean of the two:

F1 = 2 × precision × recall / (precision + recall). In this project, it is used per Fire Centre and per threshold, and the report averages those values across configurations. This is a good metric because wildfire positives are rare and raw accuracy would look artificially high.

Mean AP Average precision summarizes the whole precision-recall curve

AP is especially important for rare positive events. Instead of relying on one threshold, it measures how well the model ranks true positives above negatives across all possible decision thresholds. Higher AP means the model assigns higher risk to real hotspot events more often than to non-events. In our work, AP is a strong indicator of ranking quality, while F1 is tied to the chosen operating threshold.

Active rows These are rows with recent activity in the location history

An active row is a grid-cell-day where there has been recent hotspot activity in the recent past, typically the previous 7-day window. The project separates active vs quiet rows because they have very different behavior: active cells are much more likely to have a repeat event, while quiet cells dominate the dataset by volume but are much less likely to be positive.

Quiet rows These are rows with no recent detections in the relevant local window

A quiet row means there was no recent hotspot activity in the cell, or in the cell and neighbours for the spatial version. Quiet rows make up the majority of the dataset. Because positives are so rare, models tend to over-predict the negative class unless the training design explicitly handles class imbalance.

How Experiment 05 works

Experiment 05 is the full-data CatBoost ablation. It trains on all 2018–2021 rows without quiet-negative undersampling. It compares:

  • unweighted CatBoost on the full dataset
  • balanced CatBoost using class weights
  • cell_only vs cell_plus_neighbours features

Why do this? Because the real data are heavily skewed: most cell-days are quiet, and only a small portion are hotspot-positive. If we train on the raw data without rebalancing, the model can learn to ignore the rare event class and optimize for the majority class. This experiment tells us whether the task is mostly an imbalance problem or whether the risk signal is strong enough to learn even in the hardest setting.

Why use class weighting in the same experiment? The balanced version keeps the same data but changes the loss function so a missed hotspot is counted as more important than a correct quiet prediction. This is useful because the default objective would otherwise reward “always predict no hotspot,” which looks good in raw accuracy but fails the actual forecasting goal.

Why compare cell_only vs cell_plus_neighbours? The answer is that we want to know whether the signal is mostly local and temporal or whether nearby-cell context adds meaningful fire risk information. If the neighbour-aware version wins, it means hotspot risk is not only about a single cell’s own history but also about surrounding local activity patterns.

The point is to ask: if we do not undersample the quiet negatives, can CatBoost still learn a useful signal? This tests the model in the hardest setting: a giant majority negative class with only a small positive rate.

How Experiment 06 works

Experiment 06 is the fair baseline. It keeps every positive row, every active row, and a randomly sampled subset of quiet negatives, roughly 1%. This is the same idea used in the earlier learned baselines, so it makes the comparison fair. Because the training sample is biased toward quiet negatives being underrepresented, the model receives a corrected score at prediction time:

odds = p / (1-p), corrected_odds = odds × 0.01, corrected_probability = corrected_odds / (1 + corrected_odds).

Why do this? The majority of rows are quiet; if we train on all of them, the model spends almost all of its learning signal on the no-event class. That makes the model too conservative and often turns it into a “predict no hotspot” system. By retaining all the high-value positive and active rows and discarding a large fraction of the quiet negative rows, we make the learning problem tractable while preserving the rare-event signal.

Why is the probability correction needed? Because the training distribution is no longer the real distribution. We intentionally removed many quiet rows, so the raw model output is biased. The correction restores the probability scale so that the final score represents the real risk more faithfully. In other words, we use undersampling to learn, and then use the correction to make the score honest again.

Why do active rows stay unchanged? Because active rows are not the overwhelming majority; they are still part of the event-related signal. The real problem is the quiet negatives, not the active rows. Keeping active rows in full gives the model enough examples of the local conditions that precede hotspot activity while still making training feasible.

This is a sampling correction, not a separate calibration model. It adjusts for the fact that quiet rows were downsampled during training. Active rows are left unchanged, because they were not downsampled.

How Experiment 07 works

Experiment 07 is the first hybrid TabPFN design. The logic is:

  • score active rows with TabPFN
  • score quiet rows using the Experiment 06 CatBoost probability with the 0.01 quiet-row correction
  • choose the threshold on 2022 using F1, then apply it to 2023

Why a hybrid design at all? Because the problem is not uniform. Active rows are a small subset, but they are the hardest and most informative cases: they contain the temporal and spatial signals where hotspot risk is rising. Quiet rows are the majority and are comparatively easy to classify with a strong baseline. So it makes sense to use a stronger, more specialized model where the minority signal lives, while keeping a stable and efficient baseline for the large majority.

Why TabPFN for active rows and CatBoost for quiet rows? TabPFN is a tabular foundation model that may capture subtle structure in sparse but informative examples. That makes it attractive for active rows, where the local pattern may be unusual and the signal is concentrated. CatBoost, by contrast, is already a strong baseline for the large quiet majority and is cheaper and more stable. The hybrid approach is about dividing the workload by where each model is most useful.

Why choose the threshold on 2022 and then apply it to 2023? Because this is how we choose the operating point without leaking future information. The 2022 period acts as a validation year to pick the alert threshold that maximizes the chosen metric, and then the model is evaluated on a later, unseen year. This keeps the comparison honest and mirrors the deployment setting: train and tune on earlier years, score on a later year.

Active rows are a small but high-signal subset, so the idea is to let TabPFN handle those more difficult local patterns while keeping the strong CatBoost baseline for the majority quiet cases. It is a prototype, not a final model, but it is a useful test of whether the foundation model adds signal where the data are sparse but structurally informative.

What CatBoost is and how it works

CatBoost is a gradient-boosted decision tree model developed for tabular data. It builds a sequence of shallow decision trees that each correct the errors of the previous trees. In practice, it is strong on heterogeneous tables with mixed numerical and categorical features, and it is especially well regarded for structured prediction problems like this one.

In our task, CatBoost learns a mapping from features such as recent hotspot counts, local history, and day-of-year to a probability-like score for whether a cell-day is a recorded hotspot. The trees split on feature thresholds that best separate positive and negative examples. It works well here because the data are tabular and highly structured, and the model is fast to train relative to larger deep-learning options.

What TabPFN is and how it works

TabPFN is a tabular foundation model: a pretrained transformer that has been trained on many synthetic and real tabular datasets. Instead of training a new model from scratch on our dataset, it uses a small set of labelled examples as context and then makes a prediction for new rows in one forward pass.

For this project, the idea is: feed the model an active-row context from 2018–2021, let it rank or score new active rows, then combine that with the CatBoost quiet-row score. The main advantage is potential efficiency and strong performance on structured tabular tasks when labelled data are limited. The main limitation is that the model context size is capped, so it cannot ingest the whole dataset at once, and large-scale full-population scoring can be computationally expensive.

Why TabPFN may or may not be superior to CatBoost

TabPFN may be superior when the signal is concentrated in a specific subset, especially if the model has a strong prior over tabular patterns. It can be powerful on relatively small labeled datasets and may capture structure that a tree ensemble misses. However, it is not automatically better for every problem. In this wildfire task, the full dataset is massive and extremely imbalanced, and the majority of rows are quiet. CatBoost is simple, robust, and already has a strong baseline. TabPFN may help on the active rows, but it may also fail to scale or may not beat a well-tuned CatBoost on the full population.

So the right question is not “which model is universally best,” but “which model is strongest on the decision boundary that matters here?” In this setting, the hybrid structure is a sensible test because it leverages each model where it is strongest.

What we are trying to find in these models

We are not looking for confirmed ignition events in the traditional sense. We are trying to estimate the probability that a given grid cell on a given day will have recorded hotspot activity, using geospatial and temporal features. In other words, we are building a risk model for hotspot occurrence in space and time, using the recent local history, neighbourhood context, and seasonality as inputs.

That is why the target is a detection label from FIRMS, not a fully verified fire start. The objective is to detect unusual local risk early enough to flag where a hotspot is likely to appear or persist, not to predict final fire size or ignition certainty.

Cell_only vs cell_plus_neighbours

cell_only uses only information from the individual cell: counts over 1, 3, and 7 days, days since previous detection, left-censoring history, day-of-year, and quiet-stratum. This measures the local temporal pattern.

cell_plus_neighbours adds neighbouring grid cells and their recent counts, as well as an in-region neighbours feature. This is important because wildfire risk is spatially contagious: local ignition clusters, spread, and nearby activity often carry information that the cell alone does not. Across the runs, the neighbour-aware version usually performs better, which supports the idea that local spatial context matters.

Why a time-based split is the correct design principle

A random train/test split would be misleading in this setting because adjacent days and nearby cells are not independent. If a fire event appears in both train and test, the model can “memorize” the same spatial-temporal pattern and overstate performance. That is especially risky with wildfire data because the signal is clustered in time and space.

Training on 2018–2021 and evaluating on 2023 gives a realistic out-of-time test. It asks: can the model learn general patterns from earlier years and then detect hotspot risk in a later year without seeing those future time points? This is the right design because it reflects the actual deployment setting: forecast next-period hotspot risk from historical and current patterns, not just from random records in the same season.

Why the 02/regions data is transformed into this tabular format

The 02/regions data is not raw imagery or a single dense map. It is a transformed tabular dataset that converts geospatial wildfire dynamics into a daily cell-level forecasting table. This is the crucial engineering step that makes the model work possible.

Each region folder contains yearly feature parquet files such as features_2018.parquet through features_2023.parquet. For each region, the data are organized by grid cell and date, so each row represents one cell on one day. That layout matters because the target is a cell-day label: did a hotspot appear in this cell on this date? The features are then built from past history in that same cell and its local neighbourhood, which is why the dataset includes lagged counts such as local_count_1d, local_count_3d, local_count_7d, neighbour_count_1d, neighbour_count_3d, neighbour_count_7d, days_since_previous_detection, and history_left_censored.

Why transform the data this way? Because CatBoost and TabPFN operate on tabular rows, not on raw GIS rasters or a continuous spatial field. A tree ensemble or tabular transformer expects features in columns, with one observation per row. By reshaping the geospatial time series into cell-day rows, we can train a classifier on the same structure repeatedly across all regions and time periods. The model can then learn patterns like “this cell has had no detections for a long time,” “neighbouring cells are active,” or “the same grid cell is repeating hotspot activity over a multi-day period.”

The formatting also solves the problem of spatiotemporal dependence. Rather than modeling the whole map as one object, we create a local prediction problem: for every cell and day, predict hotspot risk from the recent local history. This makes the task computationally manageable and interpretable. It also makes the class imbalance explicit: most cell-days are quiet, but a small subset are active and rare, which is exactly the setting the sampling and threshold procedures in Experiments 05–07 are designed to handle.

In other words, the 02/regions pipeline is not just data storage; it is the conversion of a spatial wildfire process into a supervised learning problem. The resulting table is the reason the CatBoost and TabPFN experiments can train on the same feature schema across regions, tune thresholds on 2022, and evaluate on 2023 with a consistent time-based split.
