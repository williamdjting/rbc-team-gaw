01 / The idea

From scattered points to comparable places

Satellite records arrive as locations and dates. Exact coordinates can differ between observations, so comparing identical latitude–longitude pairs is a poor way to track activity in the same area. H3 assigns each point to a cell at a chosen resolution. Points assigned to that cell share an ID and can be counted together.

Cover the Earth with an indexed grid

H3 is a global system made mostly of hexagons, with 12 pentagons at every resolution. Each cell has a unique index, commonly represented as a hexadecimal string. H3 introduction

Choose a resolution

Resolutions run from 0 to 15; higher numbers mean smaller cells. The resolution determines how much spatial detail is retained. Resolution statistics

Assign each observation

h3.latlng_to_cell(latitude, longitude, 7) returns the containing resolution-7 cell. The experiment checks that the IDs in the input match this assignment.

Group by cell and UTC date

Three records in cell A on one date become one cell-day row with detection_count = 3. This is a count of records, not necessarily three different fires.

What does “hierarchical” mean?

Cells have parents at coarser resolutions and children at finer ones. A hexagonal parent has seven immediate children in the index hierarchy. This supports aggregation across scales, but the children’s geographic outlines do not fit perfectly inside the parent. Logical membership is exact; geographic containment across resolutions is approximate. Hierarchy explained

03 / Why it helps

A stable unit for space, time and comparison

Track the same area

A fixed cell ID lets us compare today with yesterday even when recorded point locations move within that cell.

Measure nearby activity

Neighbour sums provide a simple spatial signal. They can capture adjacent recorded activity, although they do not model wind, terrain or physical fire spread.

Build a regular table

One row per cell per date supports rolling counts, repeatable rules and consistent evaluation. Dates with no records remain in the table.

H3 can also provide a shared key for future weather, vegetation or terrain features once those datasets are appropriately aggregated to the same grid. Those joins are a possible extension; this experiment uses hotspot history.

04 / The implementation

How experiment 1 uses H3

Define the grid before looking at detections

prepare_daily_grid.py keeps resolution-7 cells whose polygons intersect the Kamloops Fire Centre boundary. Grid membership does not depend on where fires were later recorded.

Keep in-region observations and complete every cell-day

Only detection points inside or on the regional boundary are counted. For May–September in 2018–2023, the code creates every date × cell combination and fills missing record counts with zero. Observation coverage remains “unknown.”

Construct past-only features

run_persistence.py sums local and neighbouring counts over the previous 1, 3 and 7 days. For target date D, the window stops at D−1. The first seven days of each season are excluded from evaluation.

Apply and evaluate persistence rules

A local rule uses the cell’s history; a local-or-neighbour rule adds neighbouring history. A positive score predicts at least one recorded detection on D. The target is 1 if D has records and 0 otherwise. Rules are selected using 2022, then evaluated on 2023; 2024 is excluded.
# Simplified logic for a target cell c and date D
local = sum(count[c, day] for day in previous_days)
nearby = sum(count[n, day]
             for n in in_region_neighbours[c]
             for day in previous_days)

predict_local = local > 0
predict_local_or_neighbour = (local + nearby) > 0
target = count[c, D] > 0  # recorded activity on the target day

H3 supplies the spatial structure; the persistence rule supplies the prediction. H3 itself does not learn, forecast wildfire ignition, or estimate a probability.

05 / Choosing scale

Smaller cells give detail—and sparser histories

What is resolution?

Resolution is H3’s numbered level of spatial detail: it controls the size of the cells used to group locations. It runs from 0 (coarsest) to 15 (finest). Resolution 7 does not mean 7 kilometres or seven neighbours. It is a grid level, not a distance, and changing it does not improve the satellite’s measurement accuracy.

How does changing it work?

Moving up one level makes the average hexagon area about seven times smaller and creates roughly seven times as many cells over the same area. Moving down one level groups space more coarsely. For example, resolution 6 averages about 36.13 km² per hexagon; resolution 7 averages 5.16 km²; resolution 8 averages 0.74 km². These are global averages, not exact local cell sizes. H3 resolution statistics

When indexing the original coordinates at a finer resolution, points that shared a coarse cell can receive different cell IDs. The experiment would then rebuild its cell-day counts and neighbours at that scale. A one-step neighbourhood also covers a smaller physical area at finer resolutions. Parent–child IDs support aggregation, but their geographic boundaries only approximately nest, as explained above.

Why did we choose resolution 7?

Resolution 7 was a starting value for the baseline experiment. It provides a practical initial scale for exploring local hotspot persistence: more spatial detail than resolution 6, with less fragmentation and fewer cell-day rows than resolution 8.

This is a rationale for starting at 7, not evidence that 7 is the best scale. We did not select it through a comparison of predictive performance across resolutions. Keeping it fixed lets this experiment first examine the effect of history windows and neighbouring activity.

A useful next experiment would compare resolutions 6, 7 and 8 using the same time splits, while reporting changes in cell count, target prevalence, precision and recall. Because the prediction area changes with resolution, those scores need to be interpreted alongside the spatial scale.

06 / Reading the dataset

Active and quiet: two ways to look at a cell

A cell can have a recorded detection on one day and none on the next. Separately, this experiment selects a few active and quiet example cells using the whole May–September 2018 season. Those example groups help us inspect time series; they do not replace the daily prediction target.

Daily recorded activity

For each cell-day, a count greater than zero means a recorded detection. A count of zero means no recorded detection that day. The same cell can alternate between these states.

Active examples

Add up each cell’s records over May–September 2018. Select the three cells with the highest totals. An active example can still have many zero-count days.

Quiet examples

Find cells with zero records throughout May–September 2018. Randomly select up to three without replacement, using seed 42 for reproducibility. They may have detections in later years.

07 / Read the results correctly

What the grid cannot tell us

Zero records ≠ no fire

Missing detections can reflect observation conditions or coverage. The experiment does not establish true fire absence on zero-count days.

Cell boundaries matter

Close points can fall on opposite sides of a cell boundary. Neighbour features help include nearby activity, but can also flag cells with no next-day records.

Region edges matter

Border cells may extend outside Kamloops. Only in-region points are counted, and neighbours outside the fixed grid are omitted. Some cells therefore have fewer usable neighbours.

Cells are not exactly equal in area. A count is not an area-normalised density, a burned-area estimate or a severity measure. Repeated observations can contribute multiple records for the same ongoing fire.
